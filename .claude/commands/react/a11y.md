# Accessibility Audit (WCAG 2.1 AA)

## When to use

Use when reviewing a component before shipping, or investigating a reported accessibility issue.
Pass the component code or file path in `$ARGUMENTS`. Covers the most impactful WCAG 2.1 AA
criteria that are commonly violated in React apps.

## Instructions

Audit the component for accessibility issues, prioritizing by user impact. Check:

**Semantic HTML**
- Are interactive elements using native HTML? (`<button>` not `<div onClick>`, `<a href>` not `<div onClick>`)
- If custom elements are used, do they have the correct `role` and keyboard event handlers (Enter/Space)?
- Are headings in logical order (no skipping from `h1` to `h4`)?
- Are lists using `<ul>`/`<ol>` with `<li>`?

**Keyboard navigation**
- Can all interactive elements be reached with Tab?
- Are modals and dropdowns trapping focus correctly (focus stays inside, Escape closes)?
- Is focus restored when a modal/drawer closes?
- Are there visible focus indicators? (`:focus-visible` styles present)

**ARIA usage**
- Are ARIA attributes used correctly? (no `aria-label` on non-interactive elements, etc.)
- Do icon-only buttons have `aria-label`? (`<button aria-label="Close dialog">`)
- Do form inputs have associated `<label>` via `htmlFor`/`id` or `aria-label`/`aria-labelledby`?
- Do error messages use `aria-describedby` to associate with the input?
- Do loading states use `aria-busy` or live regions (`aria-live`)?

**Images and media**
- Do all meaningful images have descriptive `alt` text?
- Do decorative images have `alt=""`?

**Color and contrast**
- Flag hardcoded colors that might fail contrast ratio (4.5:1 for normal text, 3:1 for large text)
- Note: can't fully verify without rendering, but flag suspicious patterns

**Forms**
- Required fields marked with `aria-required` or `required`
- Validation errors announced to screen readers

## Steps

1. Read the full component JSX
2. Check each category above
3. For each issue: provide the line/element, the problem, and the corrected code snippet

## Output format

```
## Accessibility Audit: <ComponentName>

### Critical (blocks assistive technology)
- [element/line]: [issue]. Fix:
  ```jsx
  [corrected code]
  ```

### Major (WCAG AA violation)
- [element/line]: [issue]. Fix: [suggestion]

### Minor (best practice)
- [suggestion]

### Passes
- [what's correctly implemented]
```
